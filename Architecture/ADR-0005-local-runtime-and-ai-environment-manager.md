# ADR-0005: Local Runtime ManagementとAI Environment Manager

- 状態: 採用
- 日付: 2026-08-12

## 背景

ローカルAI生成は利用可能になったが、利用者がランタイムの稼働状態、モデルの保存容量、現在メモリへロードされているモデル、VRAM使用量を一画面で確認できなかった。仕様ではRustが端末の事実を収集し、UIとAIはその構造化情報を利用することを要求している。

## 決定

1. `vertex-ai-runtime`にプロバイダー非依存の`LocalRuntimeManager`契約とレジストリを置く。
2. CoreコマンドとしてAI環境の集約取得と、ロード済みモデルのメモリ解放を提供する。
3. Ollamaアダプターは公式の`/api/version`、`/api/tags`、`/api/ps`から事実を取得する。
4. 収集する情報はランタイム状態、バージョン、実行ファイル、モデル保存先、モデル名、形式、ファミリー、パラメータ数、量子化、コンテキスト長、ディスク容量、ロード状態、VRAM使用量、解放予定時刻とする。
5. AI Environment Managerは複数ランタイムを前提に集約し、Ollama固有の分岐をUIへ持ち込まない。
6. Local Runtime Managementの最初の操作は、Ollama公式の`keep_alive=0`によるモデルのメモリ解放だけとする。
7. モデル削除、保存場所移動、ランタイム停止は今回の操作範囲に含めない。これらは確認、バックアップ、検証、ロールバック設計後に追加する。
8. メモリ解放操作は構造化監査ログへ記録する。

## UI

- 「AI環境マネージャー」はランタイム数、モデル総数、モデル総容量、VRAM使用量とモデル明細を表示する。
- 「ローカルランタイム」は実行ファイル、接続先、保存先、ロード中モデルと安全なメモリ解放操作を表示する。
- ブラウザプレビューでは端末情報を取得せず、デスクトップ版が必要であることを表示する。

## 結果

現在はOllamaを最初の実装として使用するが、CoreとUIの契約はLM Studioなどの追加ランタイムを登録できる構造になった。
